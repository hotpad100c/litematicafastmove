# Litefastica（LitematicaFastMove）

让 Litematica 快到飞起。

特性：
- **独立网格**：每个投影有自己的 GPU 网格（方块、流体、叠加层），移动时只改变绘制位置，而非重建。
- **平滑移动**：显示位置以插值追上实际位置，拖动投影时不再一格一格地跳。
- **推迟提交**：大型投影连续移动时，不会每一步都重写投影世界，停手后才一次性提交。
- **后台构建**：网格在多个线程上按区段分批构建，离相机近的先出现；上传到 GPU 时有每帧预算，不会卡住画面。
- **精确重建**：只有真实世界方块变化处附近的区段会重建；如果一个区段移动前后所在的真实世界都是空气，就直接跳过。
- **多线程校验**：Configure Schematic Placement　里的 Schematic Verifier 改为多线程扫描，结果仍然显示在 Litematica 自己的校验界面里。
- **光影支持**：现在理论上能在任何光影包下正确渲染。

依赖 Litematica、malilib，以及已内嵌的 [EXIT](https://github.com/hotpad100c/emergency-exit)（让投影渲染绕过光影包）。

支持版本：26.3（主分支）、1.21.11、1.21.8、1.21.4、1.21.1、1.20.6、1.20.4、1.20.2、1.20.1、1.19.3、1.18.2、1.17.1、1.16.5（各 `port/<mc>` 分支）。

## 配置项

所有选项都注入到 Litematica 的配置界面（Generic 页，「--- Litematica Fast Move ---」分组下）。

### 基本

| 选项 | 默认 | 作用 |
|---|---|---|
| `fastMoveEnabled` 启用 | 开 | 总开关。关闭后完全回到 Litematica 原本的行为。 |
| `fastMoveTakeoverAllPlacements` 接管所有投影 | 开 | 开启时，所有投影都使用独立网格渲染；关闭时，只接管体积不小于「大型投影体积」的投影，其余仍由 Litematica 渲染。 |
| `fastMoveLargePlacementVolume` 大型投影体积 | 32768（32³） | 体积（长×宽×高）达到这个值的投影，连续移动时推迟重写投影世界，停手后再提交。关闭「接管所有投影」时，它也是决定是否接管的阈值。 |
| `fastMoveAsyncVerifier` 多线程校验 | 开 | 点击 Schematic Verifier 后用多线程扫描，直接读取投影数据，不经过投影世界。结果照常显示在 Litematica 的校验界面里。 |

### 移动手感

| 选项 | 默认 | 作用 |
|---|--|---|
| `fastMoveCommitDelay` 提交延迟（毫秒） | 1500 | 大型投影停止移动多久之后，才把新位置写入投影世界。在这之前，Easy Place、方块信息等依赖投影世界的功能看到的还是旧位置。调小后这些功能更快跟上，但连续移动时提交次数会更多。 |
| `fastMoveRenderDelay` 渲染延迟（毫秒） | 0| 投影移动后，先在原处停留这么久，再画到新位置。等待期间再次移动会重新计时，所以拖动途中的位置一次也不会被画出来，对应的重建也被省掉。适合拖动特别大的投影。 |
| `fastMoveSmoothing` 移动平滑（毫秒） | 60 | 移动插值的时间常数。越大越平滑，但跟随越「拖」；设为 0 关闭插值，直接跳到新位置。 |
| `fastMoveSnapDistance` 瞬移距离（格） | 128 | 一次移动超过这个距离时不做插值，直接瞬移，避免投影从远处一路滑过来。 |

### 性能预算

| 选项 | 默认 | 作用 |
|---|---|---|
| `fastMoveUploadKbPerFrame` 上传预算（KB/帧） | 8192 | 每帧最多上传到 GPU 的网格数据量，超出的留到后续帧。调小能减少卡顿尖峰，但投影出现得更慢。 |
| `fastMoveUploadMsPerFrame` 上传预算（毫秒/帧） | 3.0 | 每帧创建 GPU buffer 最多花费的时间，和上面的数据量预算同时生效，先用完哪个就先停。 |
| `fastMoveBuildBatchSections` 构建批次大小（区段） | 32 | 网格以多少个 16×16×16 区段为一批构建。离相机近的批次先构建，各批分散到所有构建线程并行处理。批次越小，结果出现得越早；局部重建会一批一批地生效。 |
| `fastMoveResortsPerFrame` 每帧半透明重排序数 | 32 | 每帧最多重新排序多少个含半透明方块（玻璃、水等）的区段。设为 0 不排序，半透明方块从某些角度看可能叠错。 |
| `fastMoveResortDistance` 半透明重排序距离（格） | 1.0 | 相机相对某个半透明区段移动超过这个距离后，才重新排序该区段。 |
| `fastMoveVerifierMergeMsPerTick` 校验合并预算（毫秒/tick） | 50 | 校验线程算出的结果在主线程上合并进 Litematica 校验器，这是每个 tick 合并耗时的上限，从 tick 开始时计算。调小后校验期间更流畅，但结果填满得更慢。 |

### 线程

| 选项 | 默认 | 作用 |
|---|---|---|
| `fastMoveMeshBuilderThreads` 网格构建线程数 | 0（自动） | 构建投影网格的线程数，0 表示 CPU 核数 ÷ 4（至少 1）。修改后立即生效。 |
| `fastMoveVerifierThreads` 校验线程数 | 0（自动） | 校验扫描的线程数，0 表示 CPU 核数 − 1（至少 1）。修改后立即生效。 |

### 调试

| 选项 | 默认 | 作用 |
|---|---|---|
| `fastMoveDebugGizmos` 调试框 | 关 | 在正在处理的网格区段上画会逐渐淡出的框。琥珀色：已提交重建；绿色：重建结果已生效；灰色：前后所在的真实世界都是空气，跳过；蓝色：整个投影完整重建。 |
| `fastMoveDebugGizmoDuration` 调试框时长（毫秒） | 800 | 每个调试框从出现到淡出的时长。 |

## 构建

- 单个版本：在对应分支或 worktree 里运行 `./gradlew build`。
- 全部版本：运行 `scripts/build-all.sh`，生成的 jar 收集在 `dist/` 里。

各版本移植的细节见 [PORTING.md](PORTING.md)。
